# mojo-bento v0.1.0

**Released:** 2026-10-26 · **Commit:** the one tagged `v0.1.0` · **Previous:** first release

## What it does

BentoML's serving core as a Mojo library: an epoll HTTP/1.1 server, typed JSON endpoints whose answers (success and
validation errors) are byte for byte BentoML 1.4.39's, health and Prometheus metrics, sd_notify and a graceful drain,
chunked and SSE streaming, an adaptive request batcher, a BentoML-layout model store, and `bento build` to package a
service into one directory. Linux x86-64, Mojo 1.1, no dependency but the `mojo` package.

## Highlights

- Endpoints, health, metrics and streaming answer the same bytes as BentoML on 74 + 18 + 26 request rows; the HTTP parser
  agrees with h11 on 59 raw-HTTP rows and is stricter where leniency would allow request smuggling.
- The batcher reproduces BentoML's `CorkDispatcher` decisions on 16 replayed arrival traces (batch sizes, waits,
  cancels, optimizer parameters).
- The model store reads what BentoML wrote and BentoML reads what it writes (78 operations, 368 output lines equal).

## Known limits

- HTTP/1.0 and 1.1 over IPv4 only, no TLS, no idle-connection timeout, 16384 connection slots.
- No big integers past Int64 in JSON input, no form or multipart bodies, no `split_job` in the batcher.
- `bento build` has no Python env and no Docker image; the systemd and sandbox gates run locally, not in CI.

## Upgrade / run

```
git clone https://github.com/amarbaro/mojo-bento && cd mojo-bento && uv sync
mojo run -I src examples/quickstart.mojo
```
